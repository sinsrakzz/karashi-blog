Cryptography

WARN Pikachu

Dikasih 2 file: chall.py dan output.txt.

Dari chall.py, terlihat bahwa sebuah code menghasilkan key stretching lewat PBKDF2-HMAC-SHA256, lalu hasil stretched-nya dipakai untuk menurunkan dua seed (sk_seed dan pub_seed) lewat SHA3-256 dengan domain separator "PikaSPX|sk-seed|" dan "PikaSPX|pub-seed|".

tree_height = 4, dibuat sebanyak 2⁴ = 16 leaf yang digabung untuk menghasilkan Merkle root. Flag dienkripsi menggunakan ciphertext berbasis SHAKE-256 sebagai XOR stream.

Di output.txt ada parameter code_bits = 22 — kalau dijumlah, angkanya kecil di dunia komputasi dan sangat mungkin di-solve pakai teknik brute force. Di chall.py juga ada hint:

print("Recompute the published root for every candidate code until it matches.")

Artinya kita nggak perlu membalikkan fungsi PBKDF2 atau cari kelemahan SHA256/3 cukup coba kemungkinan code dan menghitung root yang dihasilkan, lalu bandingkan ke root yang dipublikasikan.

Saya minta ChatGPT model GPT-5.6 Luna membuatkan solver brute force multiprocessing:

python
import ast
import hashlib
import os
import time
from concurrent.futures import ProcessPoolExecutor, as_completed

# ============================================================
# Load output
# ============================================================
with open("output.txt") as f:
    public = {}
    for line in f:
        if not line.strip():
            continue
        key, value = line.split("=", 1)
        public[key.strip()] = ast.literal_eval(value.strip())

CODE_BITS = int(public["code_bits"])
ROUNDS = int(public["pbkdf2_rounds"])
HEIGHT = int(public["tree_height"])
SALT = bytes.fromhex(public["salt"])
TARGET_ROOT = bytes.fromhex(public["root"])
NONCE = bytes.fromhex(public["nonce"])
CT = bytes.fromhex(public["ct"])

CODE_SPACE = 1 << CODE_BITS
LEAF_COUNT = 1 << HEIGHT

# ============================================================
# Crypto
# ============================================================
def derive_root(code):
    code_bytes = code.to_bytes(3, "little")
    stretched = hashlib.pbkdf2_hmac("sha256", code_bytes, SALT, ROUNDS, 32)

    sk_seed = hashlib.sha3_256(b"PikaSPX|sk-seed|" + stretched).digest()
    pub_seed = hashlib.sha3_256(b"PikaSPX|pub-seed|" + stretched).digest()

    nodes = []
    for index in range(LEAF_COUNT):
        idx = index.to_bytes(2, "little")
        leaf_secret = hashlib.sha3_256(
            b"PikaSPX|leaf-secret|" + sk_seed + idx
        ).digest()
        leaf = hashlib.sha3_256(
            b"PikaSPX|leaf-pk|" + pub_seed + idx + leaf_secret
        ).digest()
        nodes.append(leaf)

    while len(nodes) > 1:
        nodes = [
            hashlib.sha3_256(b"PikaSPX|node|" + nodes[i] + nodes[i + 1]).digest()
            for i in range(0, len(nodes), 2)
        ]
    return nodes[0]

# ============================================================
# Search worker
# ============================================================
def search_chunk(args):
    start, end = args
    for code in range(start, end):
        if derive_root(code) == TARGET_ROOT:
            return code
    return None

# ============================================================
# Decrypt
# ============================================================
def decrypt(code):
    code_bytes = code.to_bytes(3, "little")
    stretched = hashlib.pbkdf2_hmac("sha256", code_bytes, SALT, ROUNDS, 32)
    key = hashlib.sha3_256(b"PikaSPX|flag-key|" + stretched + TARGET_ROOT).digest()
    stream = hashlib.shake_256(key + NONCE).digest(len(CT))
    return bytes(a ^ b for a, b in zip(CT, stream))

# ============================================================
# Main
# ============================================================
if __name__ == "__main__":
    workers = min(os.cpu_count() or 1, 8)
    chunk_size = 8192
    chunks = [
        (start, min(start + chunk_size, CODE_SPACE))
        for start in range(0, CODE_SPACE, chunk_size)
    ]

    print(f"[+] Code space : {CODE_SPACE:,}")
    print(f"[+] PBKDF2     : {ROUNDS}")
    print(f"[+] Leaves     : {LEAF_COUNT}")
    print(f"[+] Workers    : {workers}")
    print(f"[+] Chunks     : {len(chunks)}")
    print("[+] Searching...")

    found = None
    with ProcessPoolExecutor(max_workers=workers) as pool:
        futures = {pool.submit(search_chunk, c): c for c in chunks}
        for future in as_completed(futures):
            result = future.result()
            if result is not None:
                found = result
                for f in futures:
                    if not f.done():
                        f.cancel()
                break

    if found is None:
        raise SystemExit("[-] Code not found.")

    flag = decrypt(found)
    print(f"[+] code = {found} (hex={found:#x})")
    print("[+] FLAG:", flag.decode())

Reverse Engineering

CRIT ITECHNO_VAULT

Binary-nya ngecek kode format ITECHNO26{...} pakai hash custom yang kalau diitung manual lumayan ribet. Daripada capek-capek nulis ulang logikanya di Python (dan resiko typo di tengah jalan), saya langsung comot byte mesin asli dari file exe, suntik ke memori yang executable, terus panggil langsung fungsinya sebagai "oracle" buat brute-force. 8 chunk, brute-force paralel, kelar kurang dari semenit.

1. Kenalan dulu sama binary-nya. Cek dulu ini file jenis apaan ternyata PE32+ (exe Windows) 64-bit, dan udah di-strip simbolnya.

$ file itechno_vault.exe
itechno_vault.exe: PE32+ executable (console) x86-64 (stripped to external PDB), for MS Windows, 10 sections

strings nemu beberapa potongan teks yang kasih clue soal alurnya: minta satu baris input ("incident code") yang harus divalidasi sesuai format ITECHNO26{...} standar keygen.

2. Bedah alur validasinya. Karena stripped, saya cari lokasi fungsi validasi dengan nge-track balik alamat string tadi (pakai objdump + strings -t x buat dapetin file offset, dikonversi ke virtual address biar ketemu instruksi lea yang makai string itu). Alurnya kira-kira:

Panjang input harus pas 51 karakter, 10 karakter pertama harus persis "ITECHNO26{", karakter terakhir harus "}", dan 40 karakter di tengah (isi flag) dicek lebih detail.

Ada beberapa lapis pengecekan: charset check (lowercase a-z, angka, underscore saja), lalu sebuah VM bytecode interpreter custom yang terlihat serem (pakai magic constant seperti 0x9e3779b9) tapi ternyata cuma decoy hasilnya selalu sukses dan buffernya nggak pernah dipakai lagi. Validasi asli: 40 karakter dipecah jadi 8 chunk @ 5 karakter, tiap chunk dicek independen lewat S-box custom (XOR + rotate) → hash mixing mirip finalizer MurmurHash3 → dibandingkan ke nilai target di data section.

3. Kenapa brute-force, bukan ngitung manual. Hash function-nya gabungan XOR + perkalian modular + shift berlapis bisa aja dibalik secara aljabar tapi effort-nya gede dan gampang salah. Untungnya tiap chunk cuma 5 karakter dengan charset [a-z0-9_] (37 karakter), jadi ruang pencarian per chunk cuma 37⁵ ≈ 69 juta kombinasi kecil, asal punya cara ngecek yang cepat dan akurat.

Triknya: comot byte .text dan .rdata dari exe apa adanya, suntikkan ke memori RWX, lalu panggil langsung fungsi validasinya sebagai oracle 100% akurat karena itu kode mesin persis yang bakal dijalankan Windows. Ini bisa jalan karena fungsi validasi per-chunk itu self-contained (nggak manggil CRT/WinAPI apa pun, cuma baca tabel data lewat alamat RIP-relative), jadi bisa dieksekusi di base address berapa aja termasuk di Linux, asal jembatan calling convention RCX/RDX (Windows) ↔ RDI/RSI (Linux) dijembatani.

4. Script solver (dibuat dengan bantuan Claude model Sonnet 5)3 file: extract.py motong section dari exe, stub.s jembatan calling convention, brute.c harness brute-force.

.intel_syntax noprefix

.global call_win64
# argumen System V masuk: rdi=alamat fungsi, rsi=win_rcx(arg1), rdx=win_rdx(arg2)
call_win64:
    push rbx
    sub rsp, 0x28        # 32-byte shadow space (+ jaga alignment 16-byte)
    mov rcx, rsi          # arg1 -> RCX (Windows ABI)
    # rdx udah pas isinya buat arg2 Windows ABI
    call rdi
    add rsp, 0x28
    pop rbx
    ret
brute.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <stdint.h>

extern int call_win64(void* func, uint64_t rcx, uint64_t rdx);

#define TEXT_VA    0x140001000ULL
#define RDATA_VA   0x140005000ULL
#define TEXT_SIZE  0x2098
#define RDATA_SIZE 0xef0
#define BUF_SIZE   (RDATA_VA - TEXT_VA + RDATA_SIZE)
#define FUNC_OFF   (0x140002700ULL - TEXT_VA)  // fungsi validasi per-chunk

int main(int argc, char** argv) {
    if (argc < 2) { fprintf(stderr, "usage: %s <chunk_index 0-7>\n", argv[0]); return 1; }
    int idx = atoi(argv[1]);

    FILE* ft = fopen("text.bin", "rb");
    FILE* fr = fopen("rdata.bin", "rb");
    unsigned char* tbuf = malloc(TEXT_SIZE);
    unsigned char* rbuf = malloc(RDATA_SIZE);
    fread(tbuf, 1, TEXT_SIZE, ft);
    fread(rbuf, 1, RDATA_SIZE, fr);
    fclose(ft); fclose(fr);

    void* mem = mmap(NULL, BUF_SIZE, PROT_READ|PROT_WRITE|PROT_EXEC,
                      MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
    if (mem == MAP_FAILED) { perror("mmap"); return 1; }
    memset(mem, 0, BUF_SIZE);
    memcpy(mem, tbuf, TEXT_SIZE);
    memcpy((char*)mem + (RDATA_VA - TEXT_VA), rbuf, RDATA_SIZE);

    void* func = (char*)mem + FUNC_OFF;
    const char* alphabet = "abcdefghijklmnopqrstuvwxyz0123456789_";
    int alen = strlen(alphabet);
    char chunk[8];
    long long total = 0;

    for (int a=0;a<alen;a++)
    for (int b=0;b<alen;b++)
    for (int c=0;c<alen;c++)
    for (int d=0;d<alen;d++)
    for (int e=0;e<alen;e++) {
        chunk[0]=alphabet[a]; chunk[1]=alphabet[b]; chunk[2]=alphabet[c];
        chunk[3]=alphabet[d]; chunk[4]=alphabet[e];
        chunk[5]=chunk[6]=chunk[7]=0;
        uint64_t rcx = (uint64_t)(uintptr_t)chunk;
        int r = call_win64(func, rcx, (uint64_t)idx);
        total++;
        if (r) {
            printf("FOUND idx=%d chunk=%.5s\n", idx, chunk);
            fflush(stdout);
        }
    }
    fprintf(stderr, "idx=%d done, tried=%lld\n", idx, total);
    return 0;
}

Dari analisis dengan radare2 (r2 -A) dan objdump: program simpan dokumen sepanjang 0x600 byte di memori. Di dalamnya ada area khusus di offset 0x3a0 sepanjang 24 byte, disebut "area segel", yang bisa dikonfirmasi lewat command katalog:

indonesia> katalog
doc_size=0x600 seal_off=0x3a0 seal_len=0x18 batas_cap=0x30
catatan: dokumen tersegel melewati audit sebelum loket dijalankan.

Isi area segel: +0x3a0 loket[0], +0x3a8 loket[1], +0x3b0 checksum. Command tampil <idx> pada dasarnya memanggil fungsi lewat pointer yang disimpan di area ini tapi sebelum memanggil, dia cek ulang hash(loket[0], loket[1]) dan membandingkannya dengan checksum tersimpan.

Analisis lebih lanjut menemukan fungsi tak terpakai di alamat 0x1ac0 tidak ada satu pun referensi statis ke fungsi ini di mana pun dalam binary. Isinya intinya: decode nama file flag.txt, fopen, fgets, lalu printf isinya. Fungsi ini sengaja ditinggal satu-satunya cara manggilnya adalah dengan mengarahkan loket[0] atau loket[1] ke alamat ini.

Command tulis <off> <byte> secara eksplisit menolak menulis ke area segel (if ((off - 0x3a0) <= 0x17) puts("tulis: area segel ditolak");). Tapi command baca <off> <len> tidak punya pengecualian yang sama cuma cek batas dokumen (off+len <= 0x600) artinya kita bisa membaca isi loket[0], loket[1], dan checksum kapan saja.

Jalur pinjam <off> lalu cap <kode> tidak dibatasi sama sekali. Byte yang benar-benar ditulis adalah hasil fungsi hash 32-bit dari (kode, off, counter_global, byte_lama), bukan kode itu sendiri secara langsung. Jalur ini tidak punya pengecekan terhadap area segel, padahal tulis punya. Karena fungsi hash-nya deterministik dan sepenuhnya bisa dihitung ulang offline (off kita tentukan, counter dibocorkan langsung lewat pesan "pinjam: antrean N siap", byte_lama bisa dibaca via bug baca), kita bisa brute-force kode (0–65535, rata-rata ~256 percobaan per byte) untuk menghasilkan byte target apa pun yang kita mau.

Kombinasi dua bug ini berarti kita bisa: bocorkan alamat fungsi, lalu timpa loket[0] byte-per-byte menjadi alamat fungsi 0x1ac0, timpa checksum byte-per-byte agar tetap konsisten, lalu panggil tampil 0 untuk memicu eksekusi fungsi pembaca flag.txt.

        kode = find_kode(off + i, counter, ob, tb)
